Requirement Overview

核心口径 / Key Decisions

1. Language mode

创建时按 Single language / Multiple languages 配置；不再按单市场 / 多市场作为主要 UI 分类。

Creation uses Single language / Multiple languages as the main UI mode, instead of Single-market / Multi-market.

2. List Attribute replaces list-kind

Allow list / Block list 与抽象 list-kind feature 均已删除；IDSP 通过 is_hit_list / is_not_hit_list + Data Source + in / not in + Active Word List Picker 配置。

Allow / Block categories and the generic list-kind feature are removed. IDSP uses is_hit_list / is_not_hit_list + Data Source + in / not in + Active Word List Picker.

3. List ID replaces API Key

对外引用与复制字段统一为 List ID；List ID 是跨版本稳定引用。

List ID is the unified external reference and copy field; it remains stable across versions.

4. Approval safety

未审批内容不进入 IDSP；Active 编辑期间旧版本持续服务；审批通过后 IDSP 自动读取最新 Active。

Unapproved content never enters IDSP; the old Active version keeps serving during edits; after approval, IDSP reads the latest Active automatically.

5. List Family → Versions

主列表按 List Name 聚合为词表族；点击 ▸ 展开该词表的 Active、Pending Review、Draft、Archive 历史版本。主行用于资产级浏览，子行用于版本级操作。

The catalog groups records by List Name as a list family. Click ▸ to expand Active, Pending Review, Draft, and Archive versions. The main row is asset-level; sub-rows are version-level.

6. Version-level List ID

主行展示当前 Active 版本的 List ID；只有 Active 版本可复制。非 Active 版本的 ID 仅用于审计，不可被 IDSP 新增引用。

The family row shows the current Active version's List ID. Only Active IDs are copyable; non-Active IDs are audit-only and cannot be newly referenced by IDSP.

Match Mode

词表匹配逻辑 / Word List Matching Logic

Mode定义 / Definition适用场景 / Scenario
Exact Match待检测文本中必须出现与词表条目逐字符完全一致的连续子串，才判定命中。工程上可用 Aho-Corasick 自动机或哈希表 + 滑动窗口实现，核心是 O(n) 与零容错。
Hit only when the checked text contains a continuous substring exactly identical to a word-list term. It can be implemented with Aho-Corasick or hash table + sliding window, with O(n) complexity and zero tolerance.		高确定性关键词、低误伤场景、需要稳定解释的规则条件。
High-confidence keywords, low false-positive tolerance, and rule conditions requiring stable interpretation.
Fuzzy Match待检测文本与词条之间的编辑距离不超过阈值时判定命中。工程上可基于 Trie + 编辑距离剪枝或 BK-tree 实现。
Hit when edit distance between checked text and a term is within a threshold. It can be implemented through Trie + edit-distance pruning or BK-tree.		对抗故意拼错、字符重复、OCR 识别错误等场景。
Used for intentional misspellings, repeated characters, OCR errors, and similar adversarial variations.

Backend Contract

后端契约 / No-page Requirements

AreaRequirement
LifecyclePending Review → Approve = Active; Pending Review → Reject = draft. Active edit creates isolated Pending Revision; rejected revision keeps current Active unchanged.
CatalogList Family is the stable asset-level grouping. Every version keeps its own status and audit record. The family row resolves the current Active version; a family without Active must not expose a copyable ID or enter IDSP candidates.
IDSP SyncIDSP only consumes Active lists. Rules store stable List ID and read the latest Active version automatically; no rule republish is required after word-list updates.
IDSP conditionA word-list condition must persist the List Attribute (is_hit_list / is_not_hit_list), one Data Source ID, operator (in / not in), and one selected Active list. Multiple lists are modeled as multiple conditions plus Logical Expression.
Schemacondition.value = { list_id, list_name_snapshot }. No type field for Allow / Block category. The backend validates that the submitted list is Active and that the Data Source is supported by the selected List Attribute.
Picker empty stateWhen no Active candidate matches, show No matching Active lists in scope with Clear filters and Open List Management. Never fall back to Draft / Pending Review / Archive results.
Trace contractReturn one condition-scoped object with feature, ds_code, ordered original_value[], and hit_lists[]. Each hit-list object contains list_id, list_name, active_version_id_at_execution, and hit-language groups. Each language group contains lang, code, and term rows with term, optional English gloss en, and boolean hit. Only actually-hit lists and languages enter the response; term context within a hit language may include non-hit rows for inspection.
Trace version resolutionHistorical Trace must resolve active_version_id_at_execution, never the current Active pointer. The original value, hit lists, language groups, matched terms, and English glosses must remain reproducible after later list updates.
Trace empty/error statesIf the configured list does not hit, return an empty hit_lists array while keeping Configured visible in Data Report. If Original Value is empty, show an inline No source value captured state. If the recorded version is unavailable, show Explanation unavailable with Trace ID, Data Source, and List ID; never silently fall back to current Active content.
ValidationValidate required columns, format, duplicates, length, accepted languages, self-review blocker, required Data Source, supported operator, and Active-list status. Return row-level errors for upload failures.
